# 架构

本文记录的决定来自实施文档 TM-001「技术选型与架构」：https://www.notion.so/4197b21c65888199b3ceed5cdc3fe071

各库的具体版本不在这里固定，由 TM-002 搭骨架时查当时的最新稳定版确定。

## 决定（维护者，2026-11-15）：运行环境

扩展分三个运行环境，三者只通过一套带类型的消息协议通信。

| 环境 | 职责 | 禁止 |
| --- | --- | --- |
| Content script（网页内） | 读取页面、渲染译文、响应用户操作 | 读取密钥、直接请求模型接口 |
| Background service worker | 全部网络请求、读取密钥、调用模型 | 保存长期内存状态 |
| 扩展页面（弹出面板、设置页） | 配置和控制 | 直接请求模型接口 |

理由：

- 网络请求和密钥集中在后台，API key 只在后台脚本中读取，页面内的脚本拿不到。
- 后台 service worker 空闲约 30 秒会被回收，所以不能在其中保存长期内存状态。

被否决的选项：TM-001 未列出。

## 决定（维护者，2026-11-15）：内核

内核只包含以下四样东西，且只做到当前功能够用为止：

1. 功能注册：每个功能实现同一个接口，在一个清单文件里登记。
2. 消息协议：一张「消息名 → 请求类型、响应类型」的表，发送和处理两端都由类型约束。
3. 设置存储：`chrome.storage.local`，读取时用 Zod 校验并补默认值。
4. 模型调用：一个 Provider 接口，第一版只有「OpenAI 兼容」一种实现。

功能接口的第一版形状：

```ts
interface Feature<S> {
  id: string;
  settings: z.ZodType<S>;                    // 该功能的设置结构与默认值
  background?(ctx: BackgroundContext): void; // 注册后台消息处理
  content?(ctx: ContentContext): void;       // 页面内逻辑
}
```

划词按钮、右键菜单、快捷键等接入点，等第一个需要它们的功能出现时再加到接口上，现在不预留。

理由：对应 TM-001 目标行为：新增一个功能等于新增 `src/features/` 下的一个目录，并在一处注册，不需要改动其他功能的代码。

被否决的选项：为之后的功能（Notion、MCP、划词等）预先设计或预留接口。TM-001 把这些列为不做的内容，未另述原因。

## 决定（维护者，2026-11-15）：目录结构

```
src/
  entrypoints/        WXT 入口：background、content、popup、options
  core/               内核：feature、messaging、settings、llm
  features/
    translate/        第一个功能
tests/
  unit/
  e2e/
```

扩展的全部源代码都放在 `src/` 下。

理由：TM-001 未单独说明。它对应 TM-001 目标行为中的「新增一个功能等于新增 `src/features/` 下的一个目录，并在一处注册」。

被否决的选项：TM-001 未列出。

## 决定（维护者，2026-11-15）：依赖规则

- `features/` 下的功能之间不得互相引用，只能引用 `core/`。
- `core/` 不得引用任何 `features/`。
- 读取密钥和调用模型的模块，只能被后台入口引用。

这三条用检查脚本强制，不靠文字约定。检查在 TM-002 中实现。

理由：TM-001 未单独说明。前两条对应目标行为「新增功能不需要改动其他功能的代码」，第三条对应「API key 只在后台脚本中读取，页面内的脚本拿不到」。

被否决的选项：只靠文字约定。

## 决定（维护者，2026-11-15）：技术选型

| 层 | 选择 | 被否决的选项及原因 |
| --- | --- | --- |
| 扩展框架 | WXT | Plasmo：维护放缓。CRXJS：只管打包，清单和多入口要自己处理。纯手写：重复造轮子 |
| 语言 | TypeScript 严格模式 | TM-001 未列出 |
| 扩展页面 UI | React | Preact、Svelte：体积更小，但第一版页面很少，体积不是问题，React 的生态和可靠性更重要 |
| 页面内译文 | 原生 DOM | 任何框架：一页可能上千段落，框架只有开销 |
| 样式 | 扩展页面用 Tailwind；注入网页的样式手写 | 全部手写：设置页表单样式工作量大 |
| 设置校验 | Zod | 手写校验：容易与类型脱节 |
| 模型调用 | 直接 `fetch` 调 Chat Completions 接口 | OpenAI 官方 SDK：只是多一层包装，且不利于以后接其他厂商 |
| 语言识别 | `chrome.i18n.detectLanguage` | 让模型判断：花钱且慢 |
| 单元测试 | Vitest | Jest：与 Vite 体系不一致 |
| 端到端测试 | Playwright 加载真实扩展，模型接口用本地假服务 | 手动测试：无法进 CI |
| 格式与检查 | Biome | ESLint + Prettier：两套工具两套配置 |
| 包管理 | pnpm | npm：安装慢，依赖隔离弱 |
| CI | GitHub Actions：类型检查、Biome、单元测试、构建、hygiene | TM-001 未列出 |

理由见上表「被否决的选项及原因」一列。

## 决定（维护者，2026-11-15）：权限

- 固定权限：`storage`、`scripting`，以及所有网站的主机权限（`<all_urls>`），安装时一次性授予。
- 虽然权限覆盖所有网站，行为仍是「点击才生效」：只有用户点击图标或按快捷键时，才向当前页面注入脚本。没有触发的页面，扩展不注入、不读取。
- 模型接口的域名已被所有网站权限覆盖，不需要单独申请。

理由：将来做按网站自动翻译时不需要再向用户申请新权限，只需另写实施文档改变行为。

代价：安装时 Chrome 会提示「读取和更改您在所有网站上的数据」。「点击才生效」因此是代码层面的约束，不再由浏览器权限保证，需要用端到端测试守住：未触发的页面上没有注入任何节点。该测试在 TM-003 中实现。

被否决的选项：只用 `activeTab`。权限最小，但之后每扩一次能力都要重新申请权限。

## 决定（维护者，2026-11-15）：密钥

- API key 存在 `chrome.storage.local`，不随账号同步到其他设备。
- 只有后台脚本读取。设置页写入后只显示掩码。
- 测试和文档中只使用假密钥。

理由：对应 TM-001 目标行为：API key 只在后台脚本中读取，页面内的脚本拿不到。

被否决的选项：`chrome.storage.sync`，因为它会随账号把密钥同步到其他设备。
